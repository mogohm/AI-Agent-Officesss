## Execution plan once credentials exist

1. Review the recovery specification (§4 requires review before generation).
2. Build deterministic prompts per asset from the spec — no ad-hoc prompting.
3. Generate candidates, max **5 attempts** per asset; on two consecutive
   identical-criterion failures, perform root-cause prompt adjustment before retry.
4. Normalize only through the approved deterministic pipeline (`imagetool.py`).
5. Deterministic validation: dimensions, format, non-zero, alpha, canvas bounds,
   transparent-edge contamination, silhouette bounds, floor-anchor compatibility,
   duplicate/near-duplicate detection, worker identity consistency.
6. Independent `VISUAL_REVIEW` AgentRun — reviewer is **not** the generator; no
   self-approval.
7. Pin approved SHA-256 per asset; compute the v1.1.0 digest.
8. Persist `canonical-baseline-v1.1.0.json/.md` and
   `baseline-attestation-v1.1.0.json/.md`. **Do not alter v1.0.0 evidence.**
9. **Durability gate (§14)** — store approved bytes in two durable locations:
   (A) git-tracked production path, and (B) durable artifact storage. Record git
   path, durable reference and SHA-256 per asset. WP-002R cannot pass until
   redundancy is proven.
10. `WP-002P-R` promotes the approved bytes using the existing executor.
11. Update `OFFICE_ASSET_BASELINE` version and digest — paths unchanged.
12. Re-run the WP-003A final gate, then resume autonomous delivery.
